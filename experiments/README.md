# 可复现实验：第一轮基线

这些是**合成场景实验**，用于验证软件和规划正式研究，不是真实用户调查结果。请保留全部输入及不可行案例，不能只报告表现最好的方案。

先启动应用，再运行：

```bash
python3 experiments/run.py
```

脚本通过真实 HTTP API 运行 8 个收入/贷款场景、3 个优化目标，以及 5 个商贷利率敏感性点。结果输出至：

- `results.json`：完整输入、计算与政策版本、可行性、三个目标下的推荐及搜索数量。
- `comparison.csv`：可以用 Excel 或 Python 分析的汇总表。

重新运行会覆盖这两个生成文件；需要保留某次实验时，应在 Git 中提交或复制至命名的实验目录。

## 本次实际运行观察

2026-10-20 的默认场景：月薪30,000元、奖金60,000元、房价300万元、首付30%、普通公积金贷款100万元、账户期初10万元。每年现金比较均扣除每月6,000元生活支出，并采用首期不用公积金冲还的保守时序。

在10–30年、每年一步、公积金金额每20万元一步、两种还款方式的252个候选中：

| 优化目标 | 第一推荐 | 首年可支配现金 | 全期总利息 |
|---|---|---:|---:|
| 首年现金最多 | 30年、组合贷、等额本息 | ¥242,429.42 | ¥1,032,207.49 |
| 全期利息最低 | 13年、组合贷、等额本息 | ¥203,678.19 | ¥417,473.49 |
| 付款成本现值最低（年折现3%） | 30年、组合贷、等额本息 | ¥242,429.42 | ¥1,032,207.49 |

这些数值只对应上述输入。13年等额本息成为最低利息的**可行**解，是同时满足逐月最低现金约束的结果；不能据此推断等额本息天然比等额本金省利息。

不使用月冲时，同一默认贷款方案首年可支配现金为¥146,723.04。月冲差额来自公积金账户支付，包含使用既有资产，不能解释为凭空增加收入。月薪15,000元的相同房价案例虽然年度合计现金为正，仍因某个月不满足现金约束而被标为不可行；这也是必须逐月检验的原因。

## 可检验的研究问题

1. 相同房价、首付和贷款利率下，等额本金减少多少总利息，初期现金压力增加多少？
2. 贷款期限变化，对首年现金流和全期总利息形成怎样的权衡？
3. 使用公积金月冲改善的是现金可用性还是新增财富？同时查看年末公积金账户余额。
4. 奖金两种计税方式在不同收入水平下是否有一致的优劣？避免从一个案例推断所有人。
5. 最低现金约束提高后，可行解集合如何缩小？无可行解应如何解释？
6. 现金流、总利息和现值三个目标是否选择同一方案？这种区别能否被用户理解？

## 答辩前需要补齐的证据

- 正式实验矩阵：收入 × 房价 × 首付 × 公积金余额 × 报价 × 约束，预先定义固定取值和指标。
- 更多独立校验：使用手工算例或另一套独立实现验证，而不是调用同一算法自证。
- 算法实验：固定候选集合，对比完整枚举与改进策略的解质量、运行时间、候选数量。
- 用户研究：取得同意后，用虚构资料进行任务测试，记录完成时间、误解和改进。不要编造参与人数或访谈。
- 平台验证：至少真实测试一台手机、一台电脑；浏览器设备模拟单独标注。
