# 项目需求、范围与验收追踪

依据：用户提供的P01 Mortgage and Income Tax Joint Calculator项目说明，以及本会话确定的Java/React Web实现方向。本文是验收标准，不是自动生成的“全部完成”声明；实际通过情况以当前版本测试记录与人工核对记录为准。

## 1. 产品目标与用户流程

用户输入工资组成、社保、公积金及购房参数，系统在明确政策和情景假设下生成个税、贷款和联合现金流结果，并在用户约束内搜索较优方案。用户能够从推荐回到原方案、逐月明细和政策依据。

主流程：

```text
加载示例或输入 → 校验 → 原方案 → 设置搜索范围 → 推荐与对比
    → 逐月明细/政策依据 → 导出 → 修改参数重新计算
```

首版适用范围：2026年宁波居民个人、同一雇主全年工资薪金、一笔符合条件的全年一次性奖金、固定确认的缴费参数、同一套房产、商贷/普通公积金贷款及组合贷、恒定利率情景。使用2026年10月核验的规则构建假设年度，不声称回溯真实1月审批或年中基数变化。它不访问银行授信或公积金实名系统，实际资格和批准范围由用户确认。

## 4. 模块与技术决策

| 模块 | 建议位置 | 责任 |
|---|---|---|
| React界面 | `frontend` | 表单、图表、错误提示、导入导出 |
| Spring Boot API | `backend/finance-api` | 请求校验、组织计算、政策展示、运行状态 |
| Java计算引擎 | `backend/finance-core` | 金额、个税、贷款、现金、优化；不依赖网页或数据库 |
| 政策资料 | `policies` | 可追溯的官方来源和版本参数 |
| 文档与报告 | `docs` | 需求、方法、限制、运行步骤和排期 |
| 验收工具 | 按仓库实际组织 | 生成合成输入、调用引擎、保存实际输出 |

核心金额采用BigDecimal；API金额格式必须前后一致。计算结果与展示层格式化分离。数据库和容器可提供部署方式，但本地启动流程不能隐瞒未启动或未验证的依赖。

## 5. 关键指标定义

- **工资到账现金**：现金收入减去个人缴费和当期实际预扣税；不包括单位公积金缴存。
- **还贷后现金**：工资到账现金减去银行现金承担的月供；本版公积金提取是对上月还款的补偿，本月只计入一次，不减少贷款合同应还总额。
- **可支配结余**：如输入生活费用，则在还贷后现金基础上再减生活费用；字段名称与优化约束要一致。
- **总利息**：各笔贷款在约定利率与还款假设下全期利息之和。
- **付款现值**：按指定折现率折现的付款成本；不自动等于个人净财富。
- **可行方案**：只表示已建模的预算、余额和用户确认范围等约束通过，不表示真实银行审批。
- **最优方案**：指定目标、候选范围及搜索步长内的最优；需要返回范围说明。

## 6. 参考案例建议

至少覆盖低收入、奖金档位边界、普通公积金5%–12%档、无公积金、余额耗尽、无贷款、零利率、尾差、同目标并列最优、无可行方案、利率变化和输入文件损坏。

参考值来自独立手算、官方示例或独立实现；不能把被测引擎输出复制成测试预期值。记录来源、舍入口径和允许误差。组合贷本金与现金账户以分为结算单位时，守恒应精确到分。
